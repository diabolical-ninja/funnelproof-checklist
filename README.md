# Contact-form delivery checklist

A practical, reusable checklist for agencies testing a client's enquiry path—from the published page to the intended inbox or CRM and the person responsible for the next step.

## What this helps you establish

- The page and form are usable.
- A clearly labelled, authorized synthetic enquiry is accepted.
- The expected confirmation appears.
- The same reference reaches the intended destination.
- Routing, ownership and notifications behave as agreed.
- The mobile path has also been checked.

A thank-you page and a dedicated test mailbox answer useful questions. Neither independently proves that the client's normal inbox or CRM received the same test.

## Run one bounded test

1. Get permission from the site and destination owner. Agree when and where to test.
2. Copy [checklist.md](checklist.md), or use the browser workbench.
3. Use synthetic data and a unique reference. Record time, scope and observations.
4. Mark each step **confirmed**, **issue found**, or **unverified**.
5. Assign an owner to unresolved issues and repeat only the affected check after a fix.

Never paste passwords, actual leads, private mailbox content, or client secrets into a public issue or repository. Keep evidence under the client's approved access controls; record a reference here only if it is safe to share.

## Scope

This is a manual workflow and test-record template. It does not run a scanner, submit forms, monitor sites, or certify delivery. A successful test describes that test at that time, not continuous availability or future revenue.

The hosted workbench is free, runs the checklist in the browser, and can export a text record. Its separate pilot research form is optional.
